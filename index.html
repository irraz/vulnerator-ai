What it is

An OODA (Observe-Orient-Decide-Act) pentest loop where the driving brain is Hermes (Nous Research) and the tools run on a Kali governed by an MCP server. Hermes decides what to run and launches it directly against the target.

A deliberately minimal design: no core, no REST API, no UI, no gates. Four containers — the agent, two MCP servers and the Caido web-security toolkit — driving the engagement end to end.

Architecture

Four containers.

  • kali

    Deterministic runtime for pentest tools: nmap, nuclei, sqlmap, ffuf, gobuster, Prowler, ScoutSuite and more. Exposes the kali-mcp server.

  • playwright-mcp

    A real headless Chromium browser exposed over MCP — the web flank for navigation, DOM and interaction, with zero native toolsets.

  • caido

    The Caido web-security toolkit — intercepting proxy, Replay, HTTPQL history, Automate fuzzing and interception — driven by kali-mcp on the internal network. Scope-guarded, zero-touch, never exposed to the host.

  • ooda-agent

    Hermes as the OODA loop driver and client of both MCP servers, running the pentest tools directly.

Engagement modes

Declare the mode at the start of every engagement. The agent enforces the scope itself.

  • mode: pentest

    Stop at exploitability evidence. Confirms the crash, documents the CVE, records CVSS, affected / patched versions and remediation steps. No root shell. Delivers an enriched Markdown + HTML report.

  • mode: redteam · ctf

    Full compromise. Exploit, escalate, capture objectives (flags, credentials, data). Uses all available resources. The agent stops only when the objective is reached or all routes are exhausted.

OODA engine

Observe → Orient → Decide → Act → Report

  • △
    Direct MCP execution — Hermes calls tools directly on Kali. No intermediate API, no validation layer, no overhead. When it calls mcp_kali_kali_run, the shell command runs for real and returns real output.
  • △
    Evidence discipline — only real tool output counts as evidence. The agent cannot cite a CVE or advisory it did not find in an actual tool result. Failed searches count as steps without progress.
  • △
    Durable finding store — record_finding / read_findings persist across context compression and session restarts. The ORIENT phase always reloads the store before reasoning.
  • △
    OODA task list — structured todo_list (OBSERVE / ORIENT / DECIDE / ACT / REPORT) survives context compression and is visible in the session chat throughout the engagement.
  • △
    Web + CLI in parallel — Playwright MCP gives the agent a real Chromium browser for web pentesting (DOM, XSS, JS-rendered SPAs) alongside Kali CLI tools. No native browser toolset.
  • △
    Two-layer pentest report — report_gen.py produces a structured Markdown base from the finding store; the agent enriches it with session context and renders a standalone HTML report with the Vulnerator-AI visual theme.
  • △
    MCP front door — the vulnerator-mcp container exposes Hermes runs as MCP tools so any MCP client (Claude Code, Kiro, custom tooling) can trigger, steer and observe a pentest programmatically.
  • △
    Hermes web dashboard — built-in browser UI at :9119 with the Vulnerator-AI skin (dark red/green cyber theme, custom OODA spinner verbs, block ASCII banner). No TUI required.

Quick start

Manual

One command. The installer asks for your OpenRouter key and brings the stack up.

bash 
git clone https://github.com/irraz/vulnerator-ai
cd vulnerator-ai
./install.sh

Lazy mode — paste into Claude Code, Kiro or Cursor

Drop this into any LLM coding assistant with shell access. It handles everything — you only provide your OpenRouter key when asked.

Full setup prompt (install + MCP wiring)

Requires Docker, Docker Compose v2 and an OpenRouter API key (or a local Ollama endpoint). Tested on macOS (Apple Silicon) and Linux x86-64.

Practice labs

Isolated, disposable Docker environments for testing the OODA agent against real vulnerabilities without internet-facing risk.

  • LPE CVE-2023-4911 x86-64

    looney-tunables-ctf

    Ubuntu 23.04 container with glibc 2.37-0ubuntu2 pinned at the vulnerable revision (pre-patch). The agent must enumerate the system, discover CVE-2023-4911 (Looney Tunables — GLIBC_TUNABLES buffer overflow in ld.so, CVSS 7.8), and either demonstrate exploitability (pentest mode) or obtain a root shell (redteam mode) using the gcc toolchain installed on the target. No hints about the vulnerability are given.

    Ubuntu 23.04 lunar · SSH access · agent_user · ASLR level 2

    pinguinazo-ssti

    Flask/Jinja2 web application with unsanitised template input. The agent must discover the server-side template injection, obtain remote code execution, establish a reverse shell to Kali, and escalate with sudo java to capture the root flag.

  • WEB CVE-2026-109618 CVE-2026-109619 Docker

    php2shell-lab

    PHP 8.2.34 vulnerable environment with nginx + PHP-FPM and Apache + mod_php. The agent must discover and exploit PHP2Shell (CVE-2026-109618 / CVE-2026-109619) — session file deserialization vulnerabilities affecting PHP 5.4.0 through 8.5.11 (pre-8.2.35 / 8.3.24 / 8.4.6). Multiple attack chains available: session upload + LFI, handler mismatch deserialization, and mod_php OOM exploitation. Real 0-day discovered January 2026.

    PHP 8.2.34 · nginx + FPM · Apache mod_php · Ports 18080 (nginx), 18081 (apache) · Chain A/C/D/E available
